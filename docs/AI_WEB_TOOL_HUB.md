# AI 网页工具协同中心

## 目标

AI 漫剧制作大师作为统一制作工作台，管理用户选择的外部 AI 网页工具与生成任务。网页工具负责实际生成；本软件负责准备上下文、组织任务、登记结果，并把下载的媒体文件导入项目素材库。

## 本阶段实现范围

- 新增前端页面 `/ai-tools`。
- 提供文本、图片、分镜、视频四类工具入口和常用网站预设。
- 允许用户添加自定义 HTTP/HTTPS 工具地址。
- 为每项任务生成结构化提示词，支持复制。
- 用户主动点击后，通过 Electron 安全 IPC 在系统默认浏览器打开网站；普通浏览器模式使用新标签页。
- 保存任务状态、提示词、结果文本和结果链接到当前桌面应用浏览器的 localStorage。
- 支持用户把网页生成的文本/剧本/分镜复制回来登记。
- 图片、视频等二进制文件由用户从目标 AI 网站下载，再通过素材库页面导入。
- 首页导航增加协同中心入口。

## 安全边界

- 不采集或保存第三方网站密码、Cookie、会话令牌。
- 不绕过验证码、登录、地区限制、付费墙或网站自动化限制。
- 不自动点击“生成/购买/充值/订阅”等会产生费用或外部副作用的按钮。
- Electron 外部链接只允许 `http:` 和 `https:` 协议，使用系统默认浏览器打开。
- 预设网站只作为快捷入口；实际可用模型、功能、额度、地区和价格以用户登录后的官方网页为准。
- 不将网页跳转描述为已完成 AI 生成，也不假设第三方网页提供可编程结果接口。
- 不自动把网页结果提交给云端 API，不发生隐式付费 fallback。

## 下一阶段扩展

1. 建立服务端持久化工具注册表和任务记录，支持项目/章节/人物/场景/镜头关联。
2. 增加结果文件导入接口：安全校验文件类型/大小、生成唯一文件名、保存到素材库并记录来源任务。
3. 对支持官方 API 的服务商优先提供 API 适配器。
4. 对明确允许自动化且有稳定接口的网页，提供独立可选适配器；默认仍由用户手动确认关键操作。
5. 为不同 AI 网站维护能力、文件导出方式、地区可用性和授权状态说明。
6. 统一结果元数据：工具、模型（如可知）、提示词、生成时间、画幅、分辨率、seed（如可得）、来源任务。

## 当前限制

本阶段是“安全网页交接 + 手动结果回收”版本，不是完整的网页 RPA。软件不会自动读取网页 DOM、绕过登录或自动抓取私有下载。工具与任务记录存储在本机浏览器 localStorage；清除应用站点数据会清除这些记录。后续应迁移到本地 SQLite，以便备份和跨页面统一管理。


## 自动提示词引擎升级

新版提示词生成器按任务类型自动组织可直接交给网页 AI 使用的制作指令：

- **文本/剧本**：剧情事件、人物动机、关系变化、时间线、场景、伏笔、场次、动作、对白、旁白和原著一致性检查。
- **图片/视觉素材**：自动区分人物、三视图、场景、道具、建筑、服装等目标；提示词包含主体特征、材质、构图、光线、画风一致性和负面约束。
- **分镜**：输出镜头号、场景、景别、机位、构图、动作、对白/旁白、镜头运动、时长及人物/场景/道具关联字段。
- **视频**：按镜头组织主体动作、起止状态、镜头运动、时长建议、参考素材、连续性约束和负面提示词。
- 根据所选工具名称调整提示词表达，例如 Midjourney、可灵和 Runway 的提示词组织建议；不会假定网站支持未确认的参数。
- 单任务与批量章节任务共用同一提示词引擎；可选择专业、电影感或简洁风格。
- 自动生成的提示词先保存在任务记录中，用户检查后复制并打开目标网站；不会自动提交网页任务、不会自动购买或产生外部费用。

提示词引擎目前基于本机可用的章节资料、任务类型、工具名称和制作规则生成，不需要额外 API Key，也不会把整本小说自动上传给第三方网站。第三方网站实际生成能力、参数支持和输出质量仍由其官方服务决定。


# 网页版 AI 协作执行系统（目标架构与验收标准）

## 1. 系统职责

**AI 漫剧制作大师是唯一的项目数据管理中心；外部 AI 网页是受委托的分析与生成执行方。**

- 软件负责：小说与章节原文、人物/场景/道具主数据、统一素材 ID、剧情状态历史、版本、分镜、项目关系、审核、数据库写入和追溯。
- 网页 AI 负责：在用户明确交接的数据范围内阅读内容、理解剧情、分析变化、编写剧本/分镜/提示词，并在网站实际支持时生成图片或其他文件。
- 协作层负责：任务编排、上下文打包、工具选择、打开网页、回传文件/文本、结构校验、人工审核、正式入库。

打开网页本身不等于已交接数据；复制提示词不等于网页已读取；网页生成不等于软件已收到结果；收到结果不等于已通过审核或写入正式数据。

## 2. 五个工作模块

### 模块 A：AI 小说深度解析中心

按用户选择的小说和章节生成最小必要上下文包，不默认上传整本小说。上下文包包括小说/章节 ID、章节编号、原文、已有角色/素材摘要、项目画风和输出 JSON Schema。网页 AI 返回结构化分析，至少覆盖：
- 人物出场、身份、年龄感、外貌、服装、伤势、装备及变化；
- 场景、地点、时间、天气、空间与光线；
- 道具、武器、服装、建筑、特殊物品；
- 事件、人物动机、关系变化、时间线、因果、伏笔；
- 证据原文引用、置信度、待确认事项。

### 模块 B：剧情状态自动追踪

AI 只能提交“变化提议”，不能直接覆盖正式设定。每项提议必须包含小说 ID、章节编号、素材名称/类别、变化类型、变化内容、原文证据、置信度和来源任务。服务端必须以数据库中的章节原文重新核对证据；通过人工确认后才写入素材状态历史。拒绝、重复、证据不匹配和找不到素材都必须有明确状态及原因。

### 模块 C：AI 素材智能匹配中心

根据分镜中的人物、场景和道具名称产生候选匹配，返回素材 ID、类别、置信度和章节适用状态。不能只凭同名自动关联；用户确认后保存镜头-素材关系和当时的状态快照。素材演变历史按章节顺序保留，不能用后续章节的装备/服装覆盖早期镜头状态。

### 模块 D：网页版 AI 任务执行中心

每项任务应持久化记录：任务 ID、项目/小说/章节/镜头关联、工具、任务类别、上下文摘要、提示词版本、状态、创建/打开/回传/审核时间和错误原因。状态至少区分：
- prepared：已准备，尚未交接；
- opened：已打开目标网页，不代表已提交；
- awaiting_result：用户已在网页执行，等待回传；
- received：已收到文本或文件；
- needs_review：结构或素材关联待人工确认；
- completed：已通过审核并完成入库；
- failed / rejected：失败或被拒绝。

优先使用网站官方 API（仅在用户配置并授权后）；普通网页使用“打开网站 + 复制上下文/提示词 + 用户手动提交 + 导入结果”的安全交接。只有在官方允许且有稳定接口时，才开发可选自动化适配器。绝不绕过验证码、登录、付费墙或网站访问控制。

### 模块 E：AI 结果接收与整理

接收文本、JSON、图片、视频、音频、字幕和文档。文件先归档到待审核区；按文件扩展名/MIME 只做初步分类，不能宣称已经理解图像/视频内容。结构化结果先校验 Schema、章节 ID、证据引用和素材 ID；通过后展示差异预览，用户确认后才写入正式数据库或关联素材。保留原始结果、提示词、来源工具、任务 ID和审核记录。

## 3. 端到端执行流程

1. 用户选择小说/章节/任务类型和目标 AI 工具。
2. 软件从数据库组装本次授权范围内的上下文包，显示将交给第三方网站的内容和大小。
3. 提示词引擎结合任务类型、工具能力和项目设定生成提示词与结构化输出规范。
4. 用户预览并确认交接；软件才复制内容并打开对应网页。
5. 用户在网页完成登录、提交、生成和下载；软件不假定网页已经执行。
6. 用户将结果文本粘贴回来，或将下载文件导入任务。
7. 软件校验 JSON/字段、章节证据、文件类型和项目归属，生成待审核提议。
8. 用户审核变化、素材匹配和镜头关联。
9. 只有审核通过的结果才写入正式数据；全过程可追溯、可拒绝、可重试。

## 4. 当前代码现状（不得夸大）

已存在的后端基础：
- `/api/web-ai/tools`、`/api/web-ai/tasks`：工具和任务记录 API。
- `/api/web-ai/tasks/{task_key}/files`：结果文件上传与列表；当前根据扩展名/MIME/文件名初步分类。
- `/api/ai-collaboration/prompt-schema`：剧情变化结构规范。
- `/api/ai-collaboration/novels/{novel_id}/proposals/import`：接收变化提议，并用数据库章节原文核验证据。
- `/api/ai-collaboration/novels/{novel_id}/proposals`、`/api/ai-collaboration/proposals/{proposal_id}/review`：提议列表和人工审核。
- `/api/ai-collaboration/storyboard/match-suggestions`、`/api/ai-collaboration/storyboard/confirm-match`：素材候选匹配与人工确认。
- FastAPI 主入口已注册 `ai_collaboration` 路由。

仍需开发/验收：
- 前端统一任务工作台与上述剧情提议/素材匹配 API 的完整连接。
- 从软件选择章节并生成“上下文包 + 提示词 + JSON Schema”的正式交接操作。
- 网页 AI 结果粘贴/JSON 导入向导、Schema 校验、差异预览与批量审核。
- 人物年龄/外貌/服装/伤势、道具归属/损坏/升级等状态时间线可视化。
- 分镜素材版本候选的章节时间适用性校验和可视化。
- 任务状态转换、失败恢复、幂等导入、操作审计和端到端自动化测试。
- 真正的网页自动读取/自动提交不是当前实现；不得承诺第三方网页会自动接收或回传。

## 5. 安全与数据边界

- 默认按章节或用户选择范围交接，不擅自上传整本小说。
- 交接前明确展示将发送给第三方的内容；用户确认后才执行。
- 不传递软件数据库凭据、AI API Key、账号密码、Cookie 或本机敏感路径。
- 外部 AI 输出一律视为不可信数据；不能执行其中的代码、SQL、路径或工具指令。
- AI 不得直接修改正式人物/素材/分镜数据；必须通过 Schema 校验和用户审核。
- 文件名、MIME、大小、扩展名、存储路径和项目归属由服务端重新校验。
- 对没有官方 API 的网站，必须如实说明是用户手动提交和手动回传。

## 6. 验收标准

- 选中一章后，系统能展示准确的小说/章节信息和本次待交接内容。
- 同一任务可生成并保存提示词、Schema 和上下文版本，任务 ID 可追踪。
- 网页生成的结构化 JSON 可导入；错误字段、无效章节和伪造原文证据会被拒绝。
- AI 提出的剧情变化默认待审核，不会直接覆盖正式素材。
- 审核通过后能按章节写入素材演变历史；审核拒绝不会改动正式素材。
- 分镜匹配显示候选素材 ID、版本和适用章节；必须由用户确认后建立关联。
- 图片/视频仅凭文件名或 MIME 不得被标记为“AI 已理解内容”。
- 任务从准备、打开、结果接收、待审核到完成的状态可查询；失败可重试且不会重复写入。
- 原有视频发布中心、发布账号、发布 API 和上传路由全部保留，不在本功能范围内删除。
