# 补丁中心设计

## 当前已实现

- 首页导航新增“补丁中心”。
- 本地 API 提供补丁状态、补丁列表、补丁详情和补丁包创建接口。
- 页面支持粘贴 Unified Diff、源代码片段或 JSON 配置补丁。
- 补丁包写入 `APP_DATA_DIR/patch-center/packages`，不写入程序安装目录。
- 生成 SHA-256、记录目标版本、格式、大小和时间。
- 单个补丁内容限制为 512 KiB；拒绝二进制差异。
- 不会把 Ollama、ComfyUI、图片/视频模型、FFmpeg 或其他大型资源塞进代码补丁。

## 当前限制（必须如实展示）

本阶段仅生成、校验基础格式并暂存补丁包；不会执行用户粘贴的代码，也不会覆盖正在运行的程序文件。API 的 `apply_supported` 明确为 false。不得对用户宣传为已经实现一键自动安装/回滚。

## 自动应用器后续验收要求

1. 只允许更新器认可的程序文件目录和文本文件类型；拒绝路径穿越、绝对路径、符号链接逃逸、二进制文件和任意脚本执行。
2. 下载/导入后校验 SHA-256、目标应用版本、补丁依赖和签名。
3. 应用前生成逐文件备份和变更预览；用户确认后在应用关闭时原子替换。
4. 应用失败自动恢复备份；保留可查看的补丁历史和一键回滚。
5. 区分代码补丁与资源补丁。模型、权重、运行时和素材采用独立增量资源包；资源未变化时绝不重复下载。
6. 支持离线导入补丁文件；在线检查更新只是可选能力，不允许强制联网或静默使用付费云服务。
7. 完成 Windows 安装版、断网环境、升级中断、损坏哈希、错误版本、路径穿越和回滚测试后，才开放“应用补丁”。

## 交付原则

普通功能修复应优先通过小型代码补丁交付。只有新增模型、运行时、字体、媒体素材等确有新增依赖时，才下载对应的独立资源增量包。补丁系统不能把完整安装包重新打包成所谓小补丁。


## 当前第二阶段进展

- 补丁创建时解析 Unified Diff 的文件头，或要求源代码/JSON 补丁明确填写目标文件。
- 仅允许修改 `apps/web/src/`、`apps/api/app/`、`apps/desktop/` 下的指定文本源码扩展名。
- 拒绝绝对路径、盘符路径、`..` 路径穿越、空路径段及白名单以外位置。
- 补丁历史显示变更文件列表。
- 新增路径白名单、路径穿越、新文件差异和暂存哈希的后端回归测试。

以上是补丁包安全校验和审阅基础，不等于补丁已经应用。下一步仍需做完整差异预览与原子更新器；不能仅凭文件头校验就执行任意粘贴代码。


## 第三阶段：只读差异预览

- 增加 `GET /api/patch-center/packages/{id}/preview`。
- 预览前重新计算 SHA-256；哈希不一致直接拒绝。
- Unified Diff 按文件和 hunk 展示新增/删除/上下文行。
- 源码片段与 JSON 补丁展示目标路径及受限长度的内容预览。
- 补丁中心页面为每个已暂存补丁提供“只读预览差异”入口。
- 新增预览解析测试。预览接口明确 `apply_supported=false`，不写入任何程序文件。

下一阶段仍要先解决打包版程序的可更新边界：桌面程序当前包含独立 API 可执行文件和 Next.js standalone 资源，不能将仓库源代码路径直接映射为已安装文件路径。自动更新器必须针对实际发布产物建立受控文件清单和原子替换机制，再实现备份与回滚。



## 第四阶段：Windows 发布产物更新清单（构建期）

- 新增 `scripts/generate-update-manifest.cjs`，在 Windows 安装包构建期间扫描真实 Next.js 构建产物。
- 清单仅登记 `web/.next/static/` 与 `web/public/` 下不超过 5 MiB 的 JS/CSS/JSON 文本文件，逐文件记录安装相对路径、大小和 SHA-256。
- 安装包将清单放入 `resources/update/manifest.json`，路径对应实际 electron-builder `extraResources` 布局。
- API EXE、Electron app.asar、桌面主进程/preload、Next.js server.js、node_modules、FFmpeg、模型、运行时和用户数据明确排除。
- CI 增加清单生成器语法检查与白名单/哈希测试。

**重要：** 这是一份构建期文件库存清单，不是签名更新授权，也不具备应用能力。当前不替换文件、不提供自动应用承诺。下一步需在安装版读取此清单，验证安装路径与基线哈希，并设计签名补丁包及应用关闭后的安全更新流程。

## 第五阶段：桌面安装版只读读取与校验

- Electron 主进程通过受控 IPC 读取 `process.resourcesPath/update/manifest.json`，渲染进程不能自行指定磁盘路径。
- 新增安装清单核验器：校验 schema、产品标识、应用版本、允许目录、扩展名、文件大小和 SHA-256。
- 仅核验 `web/.next/static/` 与 `web/public/` 下的 JS/CSS/JSON 文件；拒绝路径穿越、绝对路径、反斜杠路径和符号链接。
- 补丁中心展示当前程序版本、清单版本、声明文件数、哈希一致文件数、缺失/变化/不合规数量。
- 新增自动化测试覆盖正常校验、版本不匹配、文件变化/缺失、路径穿越和符号链接逃逸。

**本阶段边界：** 仅在桌面主进程中读取和核验，不执行补丁、不下载文件、不覆盖文件。浏览器开发模式无法读取真实安装清单。当前“可更新候选”只代表本机文件与清单基线一致，不代表补丁包已获得签名授权。

## 第六阶段：签名补丁验证、离线导入与回滚备份框架

- 新增 Ed25519 签名验证器：签名覆盖规范化后的完整补丁清单；每个文件另行核对 Base64 内容、字节数和 SHA-256。
- 补丁格式限定为数据包，只允许更新 web/.next/static/ 和 web/public/ 下的 JS/CSS/JSON 文件；不允许 Python、EXE、DLL、脚本启动器、模型、运行时或用户数据。
- 单包总量限制 20 MiB，最多 500 个文件，每个文件最多 5 MiB；拒绝重复路径、绝对路径、路径穿越和白名单外扩展名。
- 桌面端新增离线 .aicpatch / JSON 导入入口。导入后先核对签名、目标版本和文件哈希，再保存已验证包。
- 验证成功后，先为目标文件生成独立回滚快照，保存原文件内容及 SHA-256；备份目录位于用户数据目录，不在安装目录。
- 导入前还要求本机安装清单整体通过基线核验，且补丁目标必须是清单中已存在并通过哈希核验的文件；当前阶段不接受新增文件补丁。
- 回滚快照生成不会修改安装文件；当前仍未实现补丁应用或自动恢复。

### 签名密钥配置（发布前必须完成）

- 使用 node scripts/patch-tools.cjs keygen <安全的密钥目录> 在离线安全位置生成 Ed25519 密钥对。
- 私钥 patch-private.pem 必须离线保管，绝不能提交到 Git、安装包或普通补丁包；仓库 .gitignore 已忽略 PEM 文件。
- 公钥 patch-public.pem 需要由发行维护者审核后，固定写入 apps/desktop/patch-package-verifier.cjs 的 TRUSTED_PATCH_PUBLIC_KEY_PEM，然后重新构建并发布桌面程序。
- 使用签名工具：node scripts/patch-tools.cjs sign <input.json> <patch-private.pem> <output.aicpatch>。输入 JSON 的 files 项提供 path 与 content_base64，并提供 target_version。
- 当前仓库中的发行公钥仍为空，导入入口会明确拒绝所有补丁。这是有意的 fail-closed 状态；测试使用临时密钥，不会把测试密钥设为正式信任根。

### 本阶段尚未开放

1. 不会执行补丁中的代码，也不会把补丁作为脚本运行。
2. 不会替换任何安装文件；签名验证与回滚快照只是应用前准备。
3. 不会自动还原文件；回滚清单和备份已生成，真正恢复仍需后续在应用关闭时由受控更新器执行。
4. 只有正式发行公钥固定、Windows 安装版验证、文件原子替换、断电恢复和回滚测试全部通过后，才能开放应用按钮。
