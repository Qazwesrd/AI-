# 补丁中心设计

## 当前已实现

- 首页导航新增“补丁中心”。
- 本地 API 提供补丁状态、补丁列表、补丁详情和补丁包创建接口。
- 页面支持粘贴 Unified Diff、源代码片段或 JSON 配置补丁。
- 补丁包写入 `APP_DATA_DIR/patch-center/packages`，不写入程序安装目录。
- 生成 SHA-256、记录目标版本、格式、大小和时间。
- 单个补丁内容限制为 512 KiB；拒绝二进制差异。
- 不会把 Ollama、ComfyUI、图片/视频模型、FFmpeg 或其他大型资源塞进代码补丁。

## 当前限制（必须如实展示）

本阶段仅生成、校验基础格式并暂存补丁包；不会执行用户粘贴的代码，也不会覆盖正在运行的程序文件。API 的 `apply_supported` 明确为 false。不得对用户宣传为已经实现一键自动安装/回滚。

## 自动应用器后续验收要求

1. 只允许更新器认可的程序文件目录和文本文件类型；拒绝路径穿越、绝对路径、符号链接逃逸、二进制文件和任意脚本执行。
2. 下载/导入后校验 SHA-256、目标应用版本、补丁依赖和签名。
3. 应用前生成逐文件备份和变更预览；用户确认后在应用关闭时原子替换。
4. 应用失败自动恢复备份；保留可查看的补丁历史和一键回滚。
5. 区分代码补丁与资源补丁。模型、权重、运行时和素材采用独立增量资源包；资源未变化时绝不重复下载。
6. 支持离线导入补丁文件；在线检查更新只是可选能力，不允许强制联网或静默使用付费云服务。
7. 完成 Windows 安装版、断网环境、升级中断、损坏哈希、错误版本、路径穿越和回滚测试后，才开放“应用补丁”。

## 交付原则

普通功能修复应优先通过小型代码补丁交付。只有新增模型、运行时、字体、媒体素材等确有新增依赖时，才下载对应的独立资源增量包。补丁系统不能把完整安装包重新打包成所谓小补丁。


## 当前第二阶段进展

- 补丁创建时解析 Unified Diff 的文件头，或要求源代码/JSON 补丁明确填写目标文件。
- 仅允许修改 `apps/web/src/`、`apps/api/app/`、`apps/desktop/` 下的指定文本源码扩展名。
- 拒绝绝对路径、盘符路径、`..` 路径穿越、空路径段及白名单以外位置。
- 补丁历史显示变更文件列表。
- 新增路径白名单、路径穿越、新文件差异和暂存哈希的后端回归测试。

以上是补丁包安全校验和审阅基础，不等于补丁已经应用。下一步仍需做完整差异预览与原子更新器；不能仅凭文件头校验就执行任意粘贴代码。


## 第三阶段：只读差异预览

- 增加 `GET /api/patch-center/packages/{id}/preview`。
- 预览前重新计算 SHA-256；哈希不一致直接拒绝。
- Unified Diff 按文件和 hunk 展示新增/删除/上下文行。
- 源码片段与 JSON 补丁展示目标路径及受限长度的内容预览。
- 补丁中心页面为每个已暂存补丁提供“只读预览差异”入口。
- 新增预览解析测试。预览接口明确 `apply_supported=false`，不写入任何程序文件。

下一阶段仍要先解决打包版程序的可更新边界：桌面程序当前包含独立 API 可执行文件和 Next.js standalone 资源，不能将仓库源代码路径直接映射为已安装文件路径。自动更新器必须针对实际发布产物建立受控文件清单和原子替换机制，再实现备份与回滚。
